# Task dossiers and report corrections

FlashFirm now binds one real signed source-review report to one workspace.
The report, original task commitment, review policy, decisions, appeals and
notifications can be read back and exported together. This joins delivery,
source checks and review tracking. It does not complete the independent supplier
market, TEE inference or blockchain settlement.

## Use the workspace

1. Unlock the local or free cloud workspace with your privately issued token.
2. Create a task workspace. Choose **Import corrected report · no AI cost**,
   or import the original challenged report for comparison in a different workspace.
3. Inspect the delivery, sources, review, privacy and settlement gates. Expand
   individual quotations to see their exact excerpt line numbers.
4. Read or acknowledge inbox reminders. Both the dossier and acknowledgements
   survive refresh. The token stays in memory, so refresh requires unlocking again.
5. If actual reviewers are available, pin a policy referencing this exact
   `taskRoot` and submit their signed decision envelopes. The `resultRoot` is
   the exact signed report hash. No reviewer key is generated by this interface.
6. Download the dossier and verify locally:

```sh
npm run case:verify -- /path/to/flashfirm-dossier.json
# The general verifier accepts reports, revisions and dossiers too:
npm run verify -- /path/to/flashfirm-dossier.json
```

Only the pinned public-source report format is accepted. Private notes remain
separate and are not embedded in a dossier. A case is immutable; correcting it
requires a new workspace and a new review round. Closing a workspace deletes
active private notes and cancels unfinished jobs; public-report evidence and
audit metadata are retained. Closure does not execute a refund or certify erasure.

## What was corrected

The original queued model report contains a quotation whose final line omits
the Solidity documentation prefix ` * `. Exact matching correctly rejected it.
`evidence/revised-live-receipt.json` contains a separately signed operator edit
restoring the exact source characters. Its parent receipt is embedded unchanged.
The claim statement, original model response and prior critique are retained.

This is not a new model output. It makes zero model calls and cannot inherit the
original model critique's PASS. The revision is `AWAITING_NEW_REVIEW`, even when
all nine quotations match. Existing summaries require a new review. An editor's
signature establishes artifact consistency, not independent editorial identity.
`npm run report:revise` verifies and reuses the existing revision on rerun.

`npm run sources:audit` retrieves all three immutable GitHub source files, compares
their complete hashes and checks excerpt offsets. `evidence/source-audit.json`
records a successful actual retrieval. It also flags repeated exact evidence
across workers; repetition is not automatically plagiarism or a contribution
score. Semantic entailment and causal scoring still require further work.

## SDK

```js
import {FlashFirmClient} from './src/client.mjs';
const client = new FlashFirmClient({baseUrl, token});
const firm = await client.create('Source review');
await client.attachCase(firm.id, signedReceipt);
const dossier = await client.taskCase(firm.id);
const exported = await client.exportCase(firm.id);
const inbox = await client.notifications(firm.id);
await client.acknowledge(firm.id, inbox.items[0].id);
// Prepare policy from independently agreed reviewer keys; do not invent approvals:
await client.pinReview(firm.id, policy, dossier.status.receiptHash);
```

Both Node and Workers provide:

| Method | Workspace-relative endpoint | Purpose |
| --- | --- | --- |
| GET / POST | `/:id/case` | Read / bind one immutable signed public report |
| GET | `/:id/case-export` | Export the report and bound review trail |
| GET | `/:id/notifications` | Read derived persistent in-app reminders |
| POST | `/:id/notifications/:notificationHash` | Acknowledge a visible reminder |

Owner authentication and existing origin/size/rate limits apply. Node stores the
case in its AES-GCM vault; Workers encrypts it before D1 storage. D1 migration
`0002_task_cases.sql` adds database guards for closure, immutability and review
binding, including concurrent case/policy creation. Neither service executes a
payment through these endpoints. Email and push delivery are not enabled.

## Trust and recovery

The downloaded envelope includes a SHA-256 digest and signed reports/decisions.
The verifier recomputes all embedded artifacts and report/review bindings.
The digest is not a separate trusted signature: workspace title, ID, timestamps
and state do not become independently authenticated merely by being exported.
Compare against a previously trusted digest if those metadata matter.

A review policy pinned after delivery is a post-delivery review round. It does
not prove that those identities were agreed before the original work began.
Two approval keys cannot prove that two independent people reviewed a report.
The UI never imports another task's Phala quotation test or testnet payout as
this task's evidence. All settlement and confidential-inference flags stay false.

Local encrypted backup/restore tests now recover a dossier and read
acknowledgements while revoking old sessions. Cloud restore and offsite drills
remain separate operational work. Public cloud deployment evidence belongs in
`evidence/cloudflare-case-upgrade.json` only after a real remote acceptance run.
